# Publishing Calincr on Google Play

Everything needed for the Play Console, ready to copy. Images are in this folder
(`play-icon-512.png`, `feature-graphic-1024x500.png`, regenerated by `node assets/branding/render-store.cjs`
from `assets/branding`).

## 1. Create the app: the three declarations

When creating the app (name **Calincr**, default language **English (United States)**, **App**, **Free**),
Play Console asks for three confirmations. All three can be ticked:

| Declaration | Why Calincr complies |
| --- | --- |
| Developer Program Policies | Original content and assets, no ads, no purchases, no account, no data collected, no downloaded code (MediaPipe is bundled), privacy policy in the app and online, only the permissions it uses (see section 5), honest store listing (section 3). |
| Play App Signing | Required to publish app bundles (`.aab`). Google keeps the app signing key; the key EAS created is only the **upload key** (if it is ever lost, Play Console support can reset it). |
| US export laws | The app has no encryption of its own and does not use the network. Only the phone's standard system features are used, which are exempt. |

## 2. Build the app bundle

```bash
npx expo login
npx eas-cli@latest build --platform android --profile production
```

- Let EAS create and keep the keystore (it becomes the upload key). Don't delete the EAS project.
- At the end, download the `.aab` file from the link EAS prints.
- Target SDK: 36 (Android 16), as required by Google Play since 31 August 2026.
- First release: Testing → Closed testing → Create release. When asked about the app signing key, keep
  **"Let Google manage and protect your app signing key"** (recommended), then upload the `.aab`.

### Data safety

- Does your app collect or share any of the required user data types? **No.**
  Nothing leaves the phone: the camera image is analysed on the device and discarded, progress is stored locally
  (SQLite). Backups and shared pictures go only where the player chooses through the phone's share sheet
  (user-initiated, not collection by the app).
- With "No", the form ends (no encryption or deletion questions).

### Health apps declaration

- The app offers **fitness features**: it records workouts (exercises, reps, hold time) and shows activity history.
  Tick the activity / fitness tracking feature (the exact wording of the options can change: pick the one about
  tracking physical activity or workouts).
- It does **not** use Health Connect, does not read health data, and makes no medical claim.

## 5. Permissions in the final app

Checked with `npx expo prebuild` (plus the library manifests):

- `CAMERA`: rep counting in camera mode (on-device, never recorded).
- `POST_NOTIFICATIONS`, `RECEIVE_BOOT_COMPLETED`: optional local daily reminder (scheduled by the phone).
- `VIBRATE`: haptic feedback.
- `INTERNET`: added by Expo libraries (normal permission, no declaration); the app never uses the network.
- Blocked in `app.json` (`blockedPermissions`): microphone, display over other apps, storage, advertising ID.
- No exact alarms, no location, no photos/videos access: no special declaration to fill.

## 6. Closed test, then production

Personal developer accounts created after 13 November 2023 must run a **closed test with at least 12 testers
opted in for 14 days in a row** before applying for production access.

1. Testing → Closed testing → create a track, upload the `.aab`, add a release note.
2. Testers: an email list of 12+ Google accounts (friends, family). Share the opt-in link: each tester must accept
   **and install** the app from Google Play with that account.
3. Keep them opted in for 14 days (testers should open the app now and then; Google looks at engagement).
4. Dashboard → **Apply for production access**: answer the questions about the test (Google usually replies within
   7 days).
5. Production → create a release with the same `.aab` (or a newer one) → send for review.

## 7. Updates

- `npx eas-cli@latest build --platform android --profile production` (the version code goes up automatically).
- Upload the new `.aab` in Play Console, or set up `eas submit -p android` with a Google service account key
  (see Expo's "Submit to the Google Play Store" guide). Never commit that key: the repository is public.
- Bump `version` in `app.json` (1.0.0 → 1.1.0…) for the version name players see.
